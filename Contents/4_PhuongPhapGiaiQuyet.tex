\subsection{Thu thập và chuẩn bị dữ liệu}

\subsubsection{Nguồn dữ liệu: TomTom Historical Traffic Stats}

\subsubsubsection{Lý do lựa chọn TomTom API}

Dữ liệu giao thông lịch sử từ TomTom được lựa chọn làm nguồn dữ liệu chính cho đề tài vì các lý do sau:

\begin{itemize}
    \item \textbf{Độ phủ toàn diện}: TomTom cung cấp dữ liệu cho hầu hết các tuyến đường chính tại TP.HCM, bao gồm cả các khu vực trung tâm và vùng ven.
    
    \item \textbf{Chất lượng dữ liệu}: Dữ liệu được tổng hợp từ nhiều nguồn (GPS probe data, cảm biến, crowdsourcing) và đã qua xử lý, lọc nhiễu bởi TomTom.
    
    \item \textbf{Dữ liệu lịch sử dài hạn}: API cung cấp dữ liệu lịch sử từ nhiều tháng đến nhiều năm, đủ để huấn luyện mô hình học sâu.
    
    \item \textbf{Độ phân giải thời gian phù hợp}: Dữ liệu có độ phân giải 5 phút, cân bằng giữa chi tiết và khả năng xử lý.
    
    \item \textbf{Các chỉ số phong phú}: Bao gồm tốc độ thực tế, tốc độ tự do, thời gian di chuyển, độ tin cậy, giúp phân tích đa chiều.
\end{itemize}

\subsubsubsection{Cấu trúc dữ liệu TomTom}

TomTom Historical Traffic Stats API cung cấp dữ liệu theo cấu trúc phân cấp như sau:

\textbf{Thông tin Segment (Đoạn đường):}
\begin{itemize}
    \item \texttt{segmentId}, \texttt{newSegmentId}: Định danh duy nhất của đoạn đường
    \item \texttt{streetName}: Tên đường
    \item \texttt{distance}: Chiều dài đoạn đường (mét)
    \item \texttt{speedLimit}: Giới hạn tốc độ (km/h)
    \item \texttt{frc} (Functional Road Class): Phân loại chức năng đường (0-7, với 0 là cao tốc)
    \item \texttt{shape}: Tọa độ địa lý các điểm trên đoạn đường (latitude, longitude)
\end{itemize}

\textbf{Kết quả theo thời gian (segmentTimeResults):}
\begin{itemize}
    \item \texttt{timeSet}: Khung thời gian trong ngày (độ phân giải 5 phút)
    \item \texttt{dateRange}: Khoảng ngày thu thập dữ liệu
\end{itemize}

\textit{Chỉ số tốc độ:}
\begin{itemize}
    \item \texttt{harmonicAverageSpeed}: Tốc độ trung bình điều hòa (km/h)
    \item \texttt{medianSpeed}: Tốc độ trung vị (km/h)
    \item \texttt{averageSpeed}: Tốc độ trung bình (km/h)
    \item \texttt{standardDeviationSpeed}: Độ lệch chuẩn tốc độ (km/h)
\end{itemize}

\textit{Chỉ số thời gian di chuyển:}
\begin{itemize}
    \item \texttt{averageTravelTime}: Thời gian di chuyển trung bình (giây)
    \item \texttt{medianTravelTime}: Thời gian di chuyển trung vị (giây)
    \item \texttt{travelTimeStandardDeviation}: Độ lệch chuẩn thời gian (giây)
    \item \texttt{travelTimeRatio}: Tỷ lệ thời gian thực tế/lý tưởng
\end{itemize}

\textit{Độ tin cậy:}
\begin{itemize}
    \item \texttt{sampleSize}: Số lượng mẫu dữ liệu thu thập được
\end{itemize}

\subsubsection{Lựa chọn khu vực nghiên cứu}

\subsubsubsection{Tiêu chí lựa chọn}

Việc lựa chọn khu vực giao thông để nghiên cứu dựa trên các tiêu chí sau:

\begin{enumerate}
    \item \textbf{Tầm quan trọng chiến lược}:
    \begin{itemize}
        \item Các tuyến huyết mạch nối các quận trung tâm
        \item Cổng vào/ra khu vực trung tâm TP.HCM
        \item Các trục đường có lưu lượng cao và thường xuyên ùn tắc
    \end{itemize}
    
    \item \textbf{Độ phủ dữ liệu}:
    \begin{itemize}
        \item Đảm bảo có dữ liệu TomTom liên tục cho khu vực
        \item Tỷ lệ missing data dưới 10\%
        \item Sample size trung bình đủ lớn để đảm bảo độ tin cậy
    \end{itemize}
    
    \item \textbf{Tính đại diện}:
    \begin{itemize}
        \item Bao gồm nhiều loại đường: đại lộ, đường chính, đường nhánh
        \item Đa dạng về mật độ giao thông và đặc điểm vận hành
        \item Phân bố đều về không gian
    \end{itemize}
    
    \item \textbf{Khả năng kết nối}:
    \begin{itemize}
        \item Các đoạn đường có mối liên hệ trực tiếp hoặc gián tiếp
        \item Nằm trong cùng một mạng lưới liên thông
    \end{itemize}
\end{enumerate}

\subsubsubsection{Khu vực được chọn}

Dựa trên các tiêu chí trên, đề tài lựa chọn khu vực trung tâm TP.HCM được giới hạn bởi tọa độ:

\begin{itemize}
    \item Vĩ độ: 10.7535894° - 10.7969493° Bắc
    \item Kinh độ: 106.6816889° - 106.7151954° Đông
\end{itemize}

Khu vực này là khu vực trung tâm như Quận 1, với mật độ giao thông cao và hệ thống đường sá phức tạp.

\subsubsubsection{Các bước thu thập}

\textbf{Bước 1: Tạo Analysis Job}

Sử dụng \texttt{TomTomTrafficDataCollector} để tạo job phân tích khu vực:

\textbf{Bước 2: Monitoring và Download}

\begin{itemize}
    \item Poll job status định kỳ để theo dõi tiến độ xử lý
    \item Download kết quả khi job hoàn thành (định dạng JSON hoặc GeoJSON)
    \item Implement exponential backoff khi gặp rate limit
    \item Xử lý lỗi và retry logic
\end{itemize}

\textbf{Bước 3: Streaming Ingestion}

Đưa dữ liệu vào Kafka stream để xử lý theo thời gian thực

\textbf{Bước 4: Validation Processing}

Consume từ \texttt{traffic.raw}, validate và gửi vào \texttt{traffic.validated}:

\begin{itemize}
    \item Kiểm tra tính hợp lệ của segment data
    \item Validate các time results (speed, travel time trong giới hạn hợp lý)
    \item Lọc bỏ dữ liệu không đạt tiêu chuẩn
    \item Commit offset chỉ khi xử lý thành công
\end{itemize}

\textbf{Bước 5: Feature Extraction và Storage}

Consume từ \texttt{traffic.validated}, trích xuất features và lưu trữ:

\begin{itemize}
    \item Convert nested JSON structure thành flat records
    \item Batch processing (10,000 records/batch) để tối ưu hiệu suất
    \item Pipeline xử lý: Clean $\rightarrow$ Extract $\rightarrow$ Encode $\rightarrow$ Spatial $\rightarrow$ Normalize
    \item Lưu trữ vào Parquet với partitioning theo date/time
\end{itemize}

\subsubsubsection{Error Handling và Retry Strategy}

\textbf{API Request Handling:}
\begin{itemize}
    \item Exponential backoff: $\text{delay} = \text{base\_delay} \times 2^{\text{attempt}}$
    \item Maximum 3 retry attempts cho mỗi request
    \item Timeout: 30s cho mỗi request
    \item Rate limit: 100 requests/hour
\end{itemize}

\textbf{Stream Processing Handling:}
\begin{itemize}
    \item Log tất cả errors với context đầy đủ (topic, partition, offset)
    \item Không commit offset khi có lỗi xử lý
    \item Alert khi error rate vượt 5\%
    \item Dead Letter Queue cho messages không xử lý được
\end{itemize}

\subsubsubsection{Tối ưu hóa hiệu suất}

\textbf{Batch Processing:}
\begin{itemize}
    \item Aggregate multiple records trước khi lưu Parquet
    \item Sử dụng compression (snappy) để giảm storage
    \item Partitioning theo date và time\_set để query hiệu quả
\end{itemize}

\textbf{Parallel Processing:}
\begin{itemize}
    \item Kafka consumer groups cho horizontal scaling
    \item Multiple partitions trên Kafka topics
    \item Async I/O cho API requests
\end{itemize}

\textbf{Caching Strategy:}
\begin{itemize}
    \item Cache API responses để tránh duplicate requests
    \item In-memory cache cho lookup tables (FRC mapping, etc.)
\end{itemize}

\subsubsection{Tiền xử lý dữ liệu}

\subsubsubsection{Xử lý missing values}

Dữ liệu giao thông thực tế thường có missing values do nhiều nguyên nhân: lỗi cảm biến, mất kết nối, hoặc không đủ probe data. Chiến lược xử lý được implement trong \texttt{DataCleaner}:

\textbf{1. Phân loại missing patterns:}
\begin{itemize}
    \item \textit{MCAR (Missing Completely At Random)}: Xảy ra ngẫu nhiên
    \item \textit{MAR (Missing At Random)}: Phụ thuộc vào biến quan sát được
    \item \textit{MNAR (Missing Not At Random)}: Phụ thuộc vào giá trị bị missing
\end{itemize}

\textbf{2. Phương pháp imputation:}

\textit{Linear Interpolation} - Cho gaps nhỏ (< 3 time steps):
\[
v_t = v_{t-1} + \frac{v_{t+k} - v_{t-1}}{k+1}
\]

\textit{Segment-based median imputation} - Sử dụng median theo từng segment

\textit{Global median} - Fallback cho missing values còn lại

\textbf{3. Quality threshold:}
\begin{itemize}
    \item Loại bỏ segment có > 20\% missing data
    \item Đánh dấu imputed values để đánh giá độ tin cậy
\end{itemize}

\subsubsubsection{Outlier detection và xử lý}

Outliers trong dữ liệu giao thông có thể do tai nạn, sự kiện đặc biệt, hoặc lỗi đo. \texttt{DataCleaner} sử dụng kết hợp nhiều phương pháp:

\textbf{1. Statistical Methods:}

\textit{Z-score method:}
\[
z_i = \frac{x_i - \mu}{\sigma}, \quad |z_i| > 3 \Rightarrow \text{outlier}
\]

\textit{IQR (Interquartile Range):}
\[
\text{outlier if } x < Q_1 - 1.5 \cdot \text{IQR} \text{ or } x > Q_3 + 1.5 \cdot \text{IQR}
\]

\textbf{2. Combined Detection:}

Chỉ đánh dấu outlier khi cả Z-score VÀ IQR đều phát hiện (giảm false positive)

\textbf{3. Handling Strategy:}
\begin{itemize}
    \item \textbf{Capping}: Giới hạn giá trị trong khoảng $[\text{lower\_bound}, \text{upper\_bound}]$
    \item Giữ lại outliers có thể là sự kiện thực (không remove)
    \item Log tất cả outliers để phân tích sau
\end{itemize}

\subsubsubsection{Data validation}

\texttt{DataValidator} thực hiện kiểm tra tính hợp lệ trên nhiều cấp độ:

\textbf{1. Structure Validation:}
\begin{itemize}
    \item Kiểm tra required fields (segmentId, distance, shape, segmentTimeResults)
    \item Validate data types
    \item Kiểm tra nested structure
\end{itemize}

\textbf{2. Value Range Validation:}
\begin{itemize}
    \item Speed: $\text{min\_speed}$ (0 km/h) đến $\text{max\_speed}$ (120 km/h)
    \item Distance: $> 0$ và $< 10{,}000$ mét
    \item Travel time: $\geq 0$
    \item Sample size: $\geq 0$
    \item Coordinates: latitude $\in [-90, 90]$, longitude $\in [-180, 180]$
\end{itemize}

\textbf{3. Data Quality Checks:}
\begin{itemize}
    \item Missing data ratio $< 20\%$ per column
    \item Non-null values cho critical columns (segment\_id, average\_speed)
    \item Consistency checks giữa các metrics liên quan
\end{itemize}

\textbf{4. Invalid Row Removal:}
\begin{itemize}
    \item Remove rows với speed = 0 (likely errors)
    \item Remove rows với sample\_size $< 10$ (unreliable)
\end{itemize}

\subsubsubsection{Conversion và chuẩn hóa đơn vị}

\textbf{Distance Conversion:}
\begin{lstlisting}[language=Python, caption={Chuyển đổi đơn vị khoảng cách}]
# Convert from meters to kilometers
if df['distance'].max() > 10:  # Likely in meters
    df['distance'] = df['distance'] / 1000.0
\end{lstlisting}

\textbf{Derived Features:}
\begin{itemize}
    \item \texttt{free\_flow\_speed}: 95th percentile của average\_speed theo segment
    \[
    v_{\text{free\_flow}} = \text{percentile}_{95}(v_{\text{avg}})
    \]
    \item \texttt{free\_flow\_travel\_time}: $t_{\text{free\_flow}} = \frac{d}{v_{\text{free\_flow}}}$
    \item Các chỉ số này được tính tự động nếu không có trong raw data
\end{itemize}

\begin{itemize}

    \item Easy data management và cleanup
    \item Tối ưu storage với compression
\end{itemize}

\subsubsection{Pipeline tích hợp}

\texttt{TrafficDataPipeline} là class chính điều phối toàn bộ quy trình:

\begin{lstlisting}[language=Python, caption={Pipeline tích hợp}]
pipeline = TrafficDataPipeline()

# Run full pipeline
pipeline.run_full_pipeline(
    geometry=hcmc_area,
    date_from="2024-08-01",
    date_to="2024-08-31",
    job_name="HCMC Traffic Analysis"
)
\end{lstlisting}

Pipeline thực hiện tuần tự các stages:
\begin{enumerate}
    \item \textbf{Stage 1}: Batch Collection từ TomTom API
    \item \textbf{Stage 2}: Streaming Ingestion vào Kafka
    \item \textbf{Stage 3}: Validation Processing
    \item \textbf{Stage 4}: Feature Extraction và Storage
\end{enumerate}

Mỗi stage có thể chạy độc lập hoặc kết hợp, cho phép flexibility trong việc xử lý và debug.
